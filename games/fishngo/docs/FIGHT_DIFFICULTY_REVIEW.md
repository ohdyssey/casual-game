# 파이팅 난이도 설계 검토 보고서

대상: `Hook._updateUser2Struggle` (user2 = 메인 플레이 모드). 게이지 ①~⑥ 기반 HP 소모/회복 + 릴.
검토: 다관점 5렌즈 워크플로우(밸런스·게임필·구현·엣지케이스 → 종합).

## 종합 판정: **방향 타당, 문자 그대로는 위험 → 수정 적용 권고** (as-worded 적절성 5/10)

설계 의도(가장자리로 갈수록 위험·보상↑, 느슨하면 진척 손실 + 릴 풀림)는 표현력이 좋고 출시 가치가 큼. 다만 **문자 그대로** 구현하면 기존 메카닉과 충돌하는 3가지 블로커가 있어, 의도를 보존한 **수정 스펙**으로 적용해야 함.

## 블로커 3가지

**1. 소모는 이미 t에 선형 — "2배를 위에 더하면" 폭주**
현재 소모율 = `t × baseRate × sizeFactor`. 구간 중앙값 ④/⑤/⑥(t≈0.165/0.50/0.81) → 비율 **1 : 3 : 4.9** (이미 ~5배). 여기에 2배/스텝을 곱하면 ⑥/④ ≈ **10~20배 폭주**. → "선형 위에 2배 누적"이 아니라 **선형을 버리고 구간 상수로 교체**해야 진짜 2배/4배가 됨.

**2. 회복 죽음나선 (가장 위험 — 대형·고가 어종)**
현재 회복은 **크기 무관 고정**(60/24)인데 소모는 크기 비례. → 대형어는 이미 회복(48.6/s) > 최대소모(24.3/s). 여기에 4배 회복 + 기존 낙하가속(`line 685`, ~3.9배) + 릴풀림 + 60% floor 환급이 곱해지면 바늘이 한 번 왼쪽으로 흘러도 **되돌릴 수 없는 하드 실패**가 HP 88% 구간에서 발생(피니시존<12%만 보호). = 가장 잡고 싶은 대형어가 사실상 잡기 불가.

**3. 릴풀림이 옛 "re-press jump" 버그 재현**
회복 시 outward 이동은 `line 772-794`에서 의도적으로 제거했던 것. `dtSafe(0.033)+MAX_STEP(3)` 가드를 outward에도 적용하고 `_struggleVel`을 0을 가로지르게(하드리셋 X) 해야 안전.

부가: HP 계산에 dt clamp 없음(탭복귀 프레임스파이크 시 과다소모) · 게이지 아크에 **구간 분리선이 없어** 2배 점프가 "랜덤"으로 보임(`FishingScene 1953`) · 튜토리얼 4배 과회복 · 최근 커밋(④⑤⑥ 전체 타깃)과 "⑥ 단일 스윗스팟" 상충.

## 권고 수정 스펙 (의도 보존 + 안전)

| 게이지 | 소모(t≥0) /s, ×sizeFactor | 회복(t<0) /s, ×sizeFactor | 릴 |
|--------|------|------|-----|
| ⑥ 0.67~0.95 | **100** (=2×⑤) | — | 감김(빠름) |
| ⑤ 0.33~0.67 | **50** (=2×④) | — | 감김 |
| ④ 0~0.33 | **25** | — | 감김(약) |
| ③ -0.33~0 | — | **8** | (풀림 약/정지) |
| ② -0.67~-0.33 | — | **16** (=2×③) | 풀림 |
| ① -1~-0.67 | — | **32** (=2×②) | 풀림(빠름) |

- 소모: 선형 t 제거 → **구간 상수**(정확히 2배/스텝, 4배 범위, ⑥은 현재 피크와 비슷, ④는 의미있게 약함).
- 회복: **2배/스텝 유지 + ×sizeFactor 추가**(핵심 안전 수정). → 대형어도 소모>회복 ~3:1 보장 = 죽음나선 제거. 불변식: `max_heal < max_drain` (동일 |t|·size).
- 낙하가속 완화: `1+lo*3+lo²*2` → `1+lo*1.5` (좌측 페널티 삼중스택 방지).
- HP에 `dtHp=min(dt,0.033)` clamp(프레임스파이크 과소모 방지).
- 60% floor → **올리지 않는 단방향**(존 이탈 시 진척 환급 금지).
- 튜토리얼(`_tutorialNoFail`) → 배율 1배 게이트.
- 경계 jitter 완화(스텝 seam에서 떨림 제거) + 가능하면 아크에 구간 눈금 추가.

## 릴 연속 모델 (보강 "⑥→감김 / ①→풀림" 반영)
게이지가 릴 방향을 직접 구동. 안전 레일(dtSafe·MAX_STEP·_struggleVel 0교차·leash) 적용 시 구현 가능. **단 한 가지 핵심 선택 필요** → 아래 OPEN DECISION.

## OPEN DECISIONS (개발자 결정 필요)
1. **레이트 모델**: 구간상수 교체(권고, 정확한 2배/4배) vs 부드러운 곡선(`|t|^1.8`, 경계점프 없음).
2. **릴 범위**: 완전 연속(⑥감김/①풀림, 느슨하면 HP존 락에서 이탈 = 요청 충실, 안전레일 필수) vs 안전형(HP존 도달 후 락 유지, 접근 단계 ①②에서만 풀림).
3. 정확한 수치(25/50/100, 8/16/32)·목표 캐치타임(기본어 ~4-7s) 튜닝.
4. 아크에 구간 눈금 추가 여부(스텝 모델이면 가독성 위해 권장).
