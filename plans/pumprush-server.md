# 트랙 A — 서버

## S1. `apps/api` 컨테이너화 + Postgres 실배선

**왜 지금** — 현재 API 는 **메모리 저장**으로만 뜬다(`index.ts` 가 `memoryDeps()` 사용).
Postgres 어댑터(`adapters/postgres.ts`)와 스키마(`db/001_init.sql`)는 있는데 **아무 데서도 안 쓰인다.**
배포 전에 로컬에서 진짜 DB 로 도는 것을 먼저 확인한다.

**컨텍스트 브리프**
- `apps/api` = Fastify 5 + kysely + `pg`. 라우트: `auth/anon` · `profile` · `save/pumpngo` · `time` · `wallet` · `wallet/grant`.
- 토큰 = 자체 HMAC(`lib/auth.ts`), TTL 30일. **이 파일은 건드리지 않는다.**
- 어댑터 두 개가 **같은 포트를 같은 의미로** 구현한다(memory.ts 주석). 교체는 진입점 한 줄이어야 한다.

**작업**
1. `apps/api/Dockerfile` — 멀티스테이지(build → slim runtime), `PORT` 환경변수 수용.
2. `docker-compose.yml`(로컬 전용) — api + postgres 16.
3. `index.ts` — `DATABASE_URL` 이 있으면 `postgresDeps()`, 없으면 `memoryDeps()`.
4. 마이그레이션 실행 경로 확정(기동 시 1회 or 별도 명령). **⚠️ 롤백된 이력이 있다**(`30a3461`) — 실패 시 부분 적용이 남지 않는지 확인.

**검증**
```bash
docker compose up -d
curl -s localhost:8080/health                      # 200
curl -sX POST localhost:8080/api/v1/auth/anon      # 토큰 발급
docker compose restart api && curl … /api/v1/wallet # 재기동해도 잔액 유지(= 메모리가 아님)
npm run test --workspace apps/api
```

**종료 조건** — 컨테이너 재기동 후에도 데이터가 남는다. 테스트 통과.
**롤백** — `DATABASE_URL` 을 지우면 기존 메모리 모드로 즉시 복귀.

## S2. Cloud SQL + Cloud Run 첫 배포

**의존** S1 · S0(1,2)

**컨텍스트 브리프** — 목적지 스택의 첫 실물. **HA·리플리카·Redis 는 넣지 않는다**(사이징은 나중).

**작업**
1. Cloud SQL 최소 인스턴스(`db-f1-micro` 급) + DB/유저 생성, 스키마 적용.
2. Artifact Registry 저장소 생성, 이미지 푸시.
3. Cloud Run 서비스 배포 — 서울 리전, **최소 인스턴스 0**(스케일 제로), Cloud SQL 커넥터 연결.
4. Secret Manager — 서명키·DB 접속 문자열. **평문 환경변수 금지.**
5. `.github/workflows/api-deploy.yml` — main 푸시 시 빌드→푸시→배포.
6. **백업** — Cloud SQL 자동 백업 + PITR 켠다. *지갑 원장이 들어갈 DB다. 복구 못 하면 끝이다.*
7. **관측 최소선** — 구조화 로그 + 업타임 체크 + 에러 알림 경로 하나. 
   (Sentry 전면 도입은 나중이어도, **서버가 죽은 걸 모르는 상태**로는 다음 단계에 못 간다.)

**검증**
```bash
curl -s https://<cloud-run-url>/health                    # 200
curl -sX POST https://<cloud-run-url>/api/v1/auth/anon    # 토큰
# 15분 방치 후 재호출 → 콜드스타트 지연 측정(기록해 둘 것)
```

**종료 조건** — 공개 URL 로 API 가 응답한다. GitHub 푸시로 재배포된다.
**롤백** — Cloud Run 이전 리비전으로 트래픽 100% 전환.
**⚠️ 주의** — 콜드스타트 시간을 반드시 재서 기록한다. 게임 첫 진입 UX 를 좌우한다.

# 트랙 B — 클라이언트 (서버 없이 진행 가능)

## S3. `save.ts` 를 복제본 + 아웃박스 구조로 ★ 가장 중요

**의존** 없음 — **지금 당장 시작할 수 있다.**

**왜 이게 축인가** — 설계서 §0 의 한 줄이 이 단계다. 그리고 **네트워크와 무관하게 필요**하다:
코어 `StoragePort` 가 이미 비동기인데(`load(keys): Promise<…>`) 모바일 셸의 네이티브 저장소도
비동기라, **동기 `loadSave()` 를 유지하려면 메모리 복제본이 유일한 방법**이다.

**컨텍스트 브리프**
- `loadSave()` **107곳/26파일**에서 **동기** 호출. 렌더 중에도 불린다 → 비동기로 바꾸면 씬 전체가 오염된다.
- 쓰기 진입점은 `updateSave`(33) · `writeSave`(13) 둘뿐 — **여기가 아웃박스 후크 지점**이다.
- 세이브는 `localStorage['bobblerunner:v1']` 단일 JSON 블롭.

**작업**
1. 메모리 복제본 도입 — 부팅 시 1회 로드, 이후 읽기는 복제본에서 즉시 반환.
2. 쓰기 = 복제본 갱신 + **의도(intent) 큐 적재**. 지금은 큐 소비자가 "로컬에 그대로 쓰기"뿐.
3. 의도에 **멱등키** 부착(`{userId}:{runId}:{reason}` 형태) — 서버가 없어도 지금부터 붙여 둔다.
4. `@casual/core` `platform` 포트 어댑터 형태로 정리(`local` 어댑터 = 현재 동작).

**검증**
```bash
npx vitest run games/BobbleRunner            # 523+ 통과
# 헤드리스: 신규 계정 → 한 판 → 새로고침 → 진행 유지 확인
```

**종료 조건** — ⭐ **동작이 하나도 안 바뀐다.** 오프라인에서 지금과 100% 동일.
**롤백** — 모듈 단위 되돌리기(다른 파일을 안 건드리므로 깨끗하다).
**⚠️ 이 단계에서 기능을 추가하지 않는다.** 순수 구조 교체다. 섞으면 나중에 "네트워크 탓인지 구조 탓인지" 를 가를 수 없다.

## S4. 시간·난수 주입 정리

**의존** 없음 (S3 과 병렬 가능하나 **같은 파일을 건드리면 충돌** — S3 먼저 머지 권장)

**컨텍스트 브리프**
- `new Date()` **30곳/10파일** — 기간 판정·쿨다운이 기기 시계를 신뢰(G3).
- `Math.random()` **36곳** — 코스·팩·전리품·PVP(G2). **서버 재현의 전제 조건.**
- 다행히 하부 순수 함수는 이미 파라미터를 받는다: `periodIdFor(now: Date)` · `createStairs(count, rng)` ·
  `openPack(a,id,lv,rand)` · `rollChestLoot(rand)` · `pickPlacement(…,{rng})`. **호출부만 바꾸면 된다.**

**작업**
1. 단일 `now()` 공급자 — 부팅 시 서버 시간 오프셋을 받아 두고(없으면 기기 시계) 단조 시계로 보정.
2. 런 컨텍스트 `rng` — 런 시작 시 시드를 받아 `seededRng(seed)` 생성, 런 중 모든 추첨이 이걸 쓴다.
   서버가 없으면 시드를 로컬에서 만든다(동작 동일).
3. `new Date()` · `Math.random()` 직접 호출을 **0으로** 만들고, 재발을 막는 테스트/린트 규칙 추가.

**검증**
```bash
grep -rn "new Date()" games/BobbleRunner/src --include=*.ts | wc -l   # 0 목표
grep -rn "Math.random()" games/BobbleRunner/src --include=*.ts | wc -l # 0 목표
npx vitest run games/BobbleRunner
```

**종료 조건** — 같은 시드로 두 번 돌리면 **같은 코스·같은 팩 결과**가 나온다(테스트로 고정).
**롤백** — 공급자를 기기 시계/`Math.random` 으로 되돌리면 즉시 원복.

# 트랙 C — 연결

## S5. 인증 — `/auth/{provider}` + 게스트

**의존** S2 · S0(3,4)

**컨텍스트 브리프**
- 확정: **소셜(Google·Apple) + 게스트 병행**. 계정 **병합은 제공하지 않는다** — 충돌 시 택일.
- ⚠️ **App Store 4.8**: 제3자 소셜 로그인을 제공하면 Sign in with Apple 필수.
- 기존 `lib/auth.ts` 의 **토큰 발급·검증기는 그대로 쓴다.** 바뀌는 건 *신원의 출처*뿐이다.

**작업**
1. `POST /api/v1/auth/google` · `/auth/apple` — 제공자 토큰 검증 → `provider_identity` 테이블 → userId → `issueToken()`.
2. `POST /auth/guest` — 기존 `auth/anon` 을 이름만 정리(호환 유지).
3. 계정 연결 `POST /auth/link` — **이미 진행이 있는 계정이면 409 + 양쪽 요약 반환**(클라가 택일 UI 를 띄운다).
4. 스키마 마이그레이션 `002_identity.sql`.

**검증** — 제공자 토큰으로 로그인 → 같은 계정으로 재로그인 시 **동일 userId**. 충돌 시 409 + 요약.
**롤백** — 신규 라우트만 추가되므로 비활성화로 원복.

**작업** — 로그인 씬 · 약관/처리방침 페이지 · 계정 충돌 택일 UI · 연동 유도 시점(앨범 첫 페이지 완성·첫 캐릭터 구매).

⚠️ **계정 삭제 기능이 필수다 — 이걸 빼면 심사에서 반려된다.**

**검증** — 게스트로 시작→플레이→소셜 연동→재설치 후 복구되는 전 경로를 실기기에서.
**종료 조건** — 웹·네이티브 양쪽에서 로그인이 된다.

## S8. 지갑 서버 권위

**의존** S2 · S3 · (S7 과 병렬 가능)

**컨텍스트 브리프** — G1. 현재 `settleRun()` 이 보상을 계산해 `updateSave({coins})` 로 직접 쓴다.
**클라는 금액을 보내지 않는다** — 사유(reason)만 보내고 서버가 정한다.

**작업**
1. `settleRun()` 을 **보상 계산 → 서버 요청**으로 분리. 클라는 낙관적 예측치만 표시.
2. 모든 지급을 `POST /wallet/grant` 하나로(런 정산·미션 수령·페이지 보상·상점·팩).
3. 소비(경기비용·구매)도 서버 검증. `payEntryFee()` 개편.
4. 멱등키 = DB UNIQUE 제약이 최종 방어선.
5. **기존 유저 이관** — 상한 인정(확정). 상한값은 착수 시 데이터 보고 결정.

**검증** — localStorage 의 coins 를 조작해도 **서버 잔액이 안 변한다.** 같은 정산을 두 번 보내도 한 번만 지급.

⚠️ **S8 만으로는 점수 조작이 막히지 않는다.** 이 단계는 원장을 서버로 옮기고 멱등 파이프를 세울 뿐,
서버는 여전히 클라가 말한 "이번 판 점수"를 믿는다. **조작 차단은 S9 에서 완성된다.**
S8 직후를 "지갑이 안전해졌다" 고 오해하지 말 것 — 금액 계산 권한만 넘어온 상태다.
**⚠️ 오프라인** — 세션당 상한(확정) 적용. 상한 초과분은 버리지 말고 **로그로 남긴다**(어뷰징 탐지 입력).

## S9. 런 검증 V1 + V2

**의존** S2 · S4 · S8

**컨텍스트 브리프** — 명예 랭킹 확정 → **V1+V2 가 종점**. 완전 리플레이(V3)는 **하지 않는다**.

**작업**
1. `POST /run/start` → `{runId, seed, configVersion}`. 클라는 이 시드로 코스를 만든다(S4 준비 완료 전제).
2. `POST /run/finish` → 서버가 **개연성 검증**:
   - 시간 대비 계단 상한 (연타 하한 110ms = `logic/autoPlay` MIN_TAP_MS)
   - 계단당 코인 기대값 상한 — **`logic/economySim` 이 이미 분포를 안다. 시뮬레이터가 곧 검증기다.**
   - 모드 규칙(TA 는 완주해야 인정, 질주 60초 고정 …)
3. 팩 개봉을 서버로(`POST /pack/open`) — 시즌 밸런스가 확률에 걸려 있다.

**검증** — 조작된 점수가 랭킹에 오르지 않는다. 정상 플레이는 **한 건도 거부되지 않는다**(오탐 0이 더 중요).
**⚠️ 오탐이 진짜 위험이다.** 상한을 빡빡하게 잡아 정상 유저를 막으면 조작을 막는 것보다 손해가 크다.

## S11. Cloudflare 정적 이관 + 오픈 준비

**의존** S2 · S0(5,6) — **S2 이후 아무 때나 가능**

**왜 필요** — egress. 배포본 67MB, DAU 10만이면 월 ~17TB. Cloudflare 는 **egress $0**, Vercel 은 월 수천 달러.

**작업**
0. **⚠️ 전환 최소 하루 전에 현재 DNS 의 TTL 을 짧게(300s) 내려 둔다.**
   *롤백 시점에 TTL 을 줄이는 건 불가능하다 — 이미 캐시된 레코드는 만료를 기다려야 한다.*
1. Cloudflare Pages 에 `deploy/` 배포(먼저 **임시 서브도메인**으로 검증).
2. `ryanlogic.kr` DNS 전환.
3. 비밀번호 게이트 이식 · API 를 Cloudflare 프록시 뒤로(WAF·rate-limit) · `deploy:static` 스크립트 갱신.

**검증** — 임시 서브도메인에서 전 경로 통과 후 DNS 전환. 라이브 URL 200, 에셋 캐시 히트, 게이트 동작.
**롤백** — DNS 를 Vercel 로 되돌린다(0번을 안 했으면 롤백이 몇 시간 걸린다).

## S12. PVP 실기록 풀 + 실유저 리그

**의존** S7 · S9

**컨텍스트 브리프** — ⭐ **이 게임에서 가장 값싼 서버 전환**이다. PVP 를 **전적 기반**으로 이미 만들어 두어
(`logic/pvpOpponent.ts`) 실시간 서버가 필요 없다. 지금은 상대 기록을 내 기록에서 *합성*하는데,
서버가 붙으면 그 자리에 **실유저 기록**이 들어간다. 주행 연출(`tickPvpBot`)은 그대로.

**작업** — `GET /pvp/match` (내 기준선과 비슷한 유저들의 실제 기록 배급) · 리그 로스터 실유저 ·
표본 부족 시 합성 폴백(임계값은 착수 시 결정 — 설계서 미결 5번).

**검증** — 상대 기록이 실제 다른 유저의 것. 유저가 적을 때도 매칭이 성립.
